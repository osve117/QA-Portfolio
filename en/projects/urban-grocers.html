CASE STUDY · API TESTING

Urban Grocers

Functional API Testing with Postman

Test design and execution to validate endpoints, parameters, HTTP responses and invalid input handling in kit, order and delivery services.

Postman REST API HTTP Test Design Boundary Values

01 · CONTEXT

What I tested

Urban Grocers provides an API for managing kits, products, orders and delivery services. The project aimed to validate the behavior of different endpoints through HTTP requests, checking successful responses and negative scenarios.

I ran the tests in Postman, reviewing the method, endpoint, headers, body, status code and response content.

02 · STRATEGY

How I designed the tests

Positive scenarios

I validated successful operations with valid data, such as adding existing products to a kit and checking that its contents were updated.

Negative scenarios

I sent inputs that violated the expected rules to check whether the API rejected the data and handled errors gracefully.

Boundary values

I tested out-of-range values, such as negative delivery times, to identify validation failures in the services.

Response validation

I compared the HTTP status code and response body with the expected behavior to identify backend inconsistencies.

03 · FINDINGS

Key defects

1

Negative delivery time causes an internal error

When sending deliveryTime: -1 to the courier verification service, the API returned 500 Internal Server Error instead of handling the invalid input with a controlled response.

2

Negative quantity accepted by the API

When adding a product with a negative quantity to a kit, the backend returned 200 OK and stored negative values in quantity and productsCount.

04 · RESULTS

What the project demonstrates

This project demonstrates my ability to build HTTP requests, work with JSON data, validate response codes and identify validation problems that are not always signaled by an error status code.

It also provided practice in positive and negative test design, boundary values and analysis of how a backend actually handles invalid inputs.
