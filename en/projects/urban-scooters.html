CASE STUDY · QA

Urban Scooters

Web, API and Mobile Testing

Validation of the order creation and processing workflow through requirements analysis, test design, manual execution, API testing and defect documentation.

Manual QA API Testing Mobile Testing Postman Jira Android Studio DevTools

01 · CONTEXT

What I tested

Urban Scooters is a QA project focused on a scooter rental and management system. The work covered web components, API services and a mobile application used to process orders.

The objective was to verify that the order workflow met the requirements, from data entry and order creation through subsequent management in the application.

02 · CONTRIBUTION

My role

I analyzed requirements, designed and executed tests, prepared data through the API and documented defects with expected results, actual results and supporting evidence.

Test design

Checklists, test cases, and positive and negative validation scenarios.

API

HTTP requests to create orders and prepare the data needed for testing.

Mobile

Testing on mobile devices and emulators to validate order states, notifications and interface behavior.

Defects

Bug reports in Jira with reproduction steps, expected and actual results, severity and evidence.

03 · PROCESS AND DECISIONS

How I approached testing

1

Requirements analysis

I reviewed the requirements to identify the main workflows, validation rules, order states and conditions to test.

2

Coverage design

I organized checks by feature and used positive and negative scenarios, equivalence classes and boundary values where applicable.

3

Test data preparation through the API

I used API requests to create orders and obtain the necessary data before validating behavior in other system components.

4

Execution and reproduction

When unexpected behavior appeared, I repeated the scenario and varied the test conditions to determine whether the issue was reproducible.

5

Documentation

I documented defects in a structured format and linked each finding to the expected behavior defined in the requirements.

04 · FINDINGS

Examples of issues identified

During execution, I identified functional, visual and behavioral defects that I could reproduce and document with evidence.

NOTIFICATIONS · US-26

Expected notification not received

The notification expected two hours before the order ended was not received during test execution.

MOBILE · US-29

Duplicate order in “My orders”

After accepting a single order, the mobile application displayed more than one card for the same order.

ORDER STATUS · US-4

Status sequence contains fewer stages than required

The status screen showed four stages, while the requirement specified a sequence of five states.

WEB · US-7

Placeholder displayed instead of the rental end date

While the ride was in progress, the interface displayed {{data}} instead of the calculated rental end date.

05 · RESULTS AND LEARNING

What I learned

This project allowed me to practice a complete QA workflow: interpreting requirements, designing coverage, preparing data, testing different components and turning unexpected behavior into clear, reproducible bug reports.

It also reinforced the importance of investigating issues across system layers. Combining web, API and mobile testing helped me compare behavior and gather stronger evidence before reporting an issue.
